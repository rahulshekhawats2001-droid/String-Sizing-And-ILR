    RESEARCH BOUNDARY

    Academic model vs bankable plant engineering

    This research engine is a transparent screening / comparative model. A bankable utility-scale design still requires high-resolution measured or bankable met data, exact PAN/OND or equivalent equipment models, detailed tracker/layout/shading analysis, cable schedules, soil/geotechnical inputs, protection/earthing studies, grid studies, certified equipment and verified procurement quotations. The website deliberately labels these boundaries instead of silently filling them.

    SOURCE POLICY

    How this website chooses a source

    1. Current authoritative source first

    Current regulation, government eligibility, manufacturer specifications, live datasets and project prices are sourced from current authoritative sources. The 2021 book is not the controlling source for current facts.

    2. Book = foundational concept reference

    The uploaded book supports PV concepts, design sequence and terminology. Where the website needs a current code, current dataset, manufacturer value, price or project requirement, the external authoritative source controls.

    3. Manufacturer data for equipment

    Module and inverter electrical/physical specifications must come from the selected manufacturer's official datasheet/manual whenever possible.

    4. No silent fabrication

    Unavailable prices, specifications or resource values remain marked as unavailable or require user input. Benchmarks are never labelled as actual procurement prices.

    5. Research papers as model evidence

    The 55-paper reference bank is used to define the research variables, trade-offs, constraints and candidate-analysis workflow. Paper-level detailed claims remain limited to available evidence; the dashboard links each paper to its source page.

    6. Traceability in reports

    Exported reports should carry the source register, formula references, book sections, manufacturer documents, regulatory references and user assumptions used for that run.

    Key takeaways

    • Piling & structures is the pacing activity — downstream stages cannot outrun it.
    • The substation/switchyard and transmission line must start first even though they finish last — the single most common cause of delay at both scales.
    • Rajasthan's pre-monsoon dust-storm and extreme-heat window (April–June) constrains outdoor productivity and safety planning at both scales.
    • A 100 MW project's overall development-to-COD cycle is 24–36 months; a 5 MW project's is 9–15 months — the same gates, compressed.
